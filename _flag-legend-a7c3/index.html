Lead Flag Legend — every flag we have or could use

PROPOSAL for Ted. Mark each row keep / cut. This is the full inventory of property-lead flags: the ones already on crm.hit_list, the ones sitting unused in our cached REAPI payloads (zero API cost to apply), and the court/document pulls we could sell. Every flag gets a source, a confidence tier, a card chip, a plan tier, and a rule (auto-apply or propose-only, plus the key that reverts it). Counts are live from the database as of 2026-10-03: 39,708 active hit_list rows and 36,574 cached REAPI PropertyDetail payloads (plus 26,553 PropertyRecord rows not counted here). Nothing on this page is final until Ted marks it.

Legend key

Confidence tier (Ted: "Never guess on deceased flags")
CONFIRMED obituary / SSA death index / probate filing / court caption / Ted confirmed. Shown as fact.
RECORD SIGNAL a county-record or vendor flag (REAPI death=true, Leavitt list, PACER name match). Shown as a signal WITH its source. Never shown as a confirmed death.
INFERRED name / age / address heuristics. Never auto-applied. Proposal list only, with the evidence behind it.
Plan tier (real gates in server.py)
FREE sees status, equity %, AVM, sale date and property facts. strip_contacts() withholds phones, emails, equity $ and loan balance server-side.
PRO $49 is_paid(): contacts, equity $, court records (CourtListener), skip trace (200/mo), export (2,000 rows).
PREMIUM $99 has_premium(): everything in PREMIUM_COLS = next_of_kin, deceased_party, probate_case_number, bankruptcy_case / _title / _link / _active_stay. Export 5,000 rows.
Action
AUTO-APPLY set on the row by a cron or the enrich step, with a source label, reversible by that label.
PROPOSE-ONLY written to a review list / tag, never to the hard flag, until a human or a confirming source promotes it.
PRO PULL runs only when a paid user taps it (JIT). Result cached forever on the row.
NOT STORED exists in the payload or a vendor, nothing on hit_list yet.
Two honest gaps the code has today. (1) bankruptcy_flag and bankruptcy_chapter are NOT in PREMIUM_COLS, so Pro and Free rows carry them unstripped; only the case number / title / link / active-stay are Premium-only. Proposed: add both to PREMIUM_COLS. (2) absentee_tier is populated on every row but 38,162 of 39,708 say unknown; the REAPI absentee flags below are the real signal and are not yet copied over.

Pull-credit rules (proposed)
1. Premium: 5 document pulls per month included, then $5 each. Pro: $5 each, no included pulls. Free: cannot pull.
2. A pull is charged once per document per property, ever. Second user who taps the same doc gets the cached copy at $0 and we do not re-bill.
3. RECAP is checked first (free). PACER is hit only on a RECAP miss and the fetched PDF is pushed back to RECAP so the next one is free for everyone.
4. Hard cap $3 of PACER per document (30 pages); anything longer is served as the docket sheet + first 30 pages.
5. Every pulled document is stamped with pulled_at, pulled_by, source (recap / pacer), cost_cents — same source-label discipline as flags.

G Global rules

  1. Source label mandatory. No flag is written without a source string (deceased_source, tag name, enrichment_source, verified_source, sale_verified_source). A flag with a NULL source is a bug and gets reverted.
  2. Three confidence tiers, shown on the chip. CONFIRMED (obituary / SSA / probate filing / court caption / Ted) → RECORD SIGNAL (REAPI county-record flags, Leavitt list, PACER name match, CourtListener hit) → INFERRED (heuristics). A RECORD SIGNAL is never rendered as a confirmed fact; the chip says "signal" and names the source.
  3. Reversible by source. Every applied flag can be undone with one statement keyed on its label, e.g. where deceased_source='reapi-death', array_remove(tags,'reapi-inherited'), where bankruptcy_confidence='cross-state'.
  4. Enrich once, freeze. Property data is pulled once and frozen on the row. All REAPI-derived flags on this page come from the cached payload in crm.reapi_properties at zero API cost. Re-pulls happen only on a paid tap and are stamped.
  5. Never auto-apply INFERRED. Heuristic matches go to a review list / proposal tag. Promotion needs a CONFIRMED or RECORD source or Ted.
  6. Tier gates are real and server-side. Free: status, equity %, AVM, sale date, property facts, and every chip. Pro: contacts, equity $, loan balance, court records, skip trace, export. Premium: next_of_kin, deceased_party, probate_case_number, bankruptcy case / title / link / stay, document pulls. Proposed fix: add bankruptcy_flag and bankruptcy_chapter to PREMIUM_COLS.
  7. Card shows at most 3 chips, picked in this priority order: ① AUCTION date (≤45d) ② BK STAY / BK SURRENDER ③ DECEASED (confirmed) or UNKNOWN HEIRS ④ DEATH SIGNAL / INHERITED ⑤ ON MLS / FAILED LISTING ⑥ VACANT ⑦ ABSENTEE (out-of-state before in-state) ⑧ FREE & CLEAR / EQUITY % ⑨ REVERSE MTG ⑩ TAX LIEN / JUDGMENT ⑪ JUDICIAL ⑫ everything else in detail only. Status (PRE-FC / SCHEDULED) is the row's base state, not one of the 3.
  8. Every chip is tappable and opens: source label, the date it was set, the raw evidence (payload field, notice URL, obit URL, case #), confidence tier, and the revert key. Same sheet for Free and paid; paid tiers just see more underneath.
  9. Archiving needs a reason. REO, sold-after-notice and cured rows go to a review list with the proposed archived_reason; nothing is deactivated automatically.
  10. Vendor "not set" ≠ false. A missing REAPI flag means unknown, especially mls_active in ID/MT. Chips are only drawn on explicit true.
