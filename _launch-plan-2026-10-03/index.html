Two Apple risks to plan for now. Guideline 4.2 rejects thin web wrappers. The shell must add something native: push alerts for new auctions in saved states and a native share sheet are enough. Guideline 3.1.1 requires in-app purchase for digital subscriptions. OffRamp sells data access, which Apple treats as digital. Options: ship the native app as sign-in only with no upgrade button and buy on the web, or request the External Link Account entitlement, or add StoreKit subscriptions mirroring Pro and Premium and accept the 15 percent small business rate. Recommendation for launch: native app = sign-in and use only, upgrade lives on the web, no payment mention inside the app. Item 19 in the master file already points the native upgrade screen at a web link. Remove that link for the first review build.

6. Launch-day runbook

  1. Freeze. No data merges or schema changes from Sat noon until Sun 1 PM. Feed cron may run. Nothing else touches hit_list.
  2. Backup. Supabase snapshot of hit_list, offramp_users, offramp_credit_ledger, offramp_lead_actions before the switch. Keep the file in the vault.
  3. Smoke test. node scripts/app_smoke.mjs against 200 live rows. Must print PASS.
  4. Server boot check. Boot server.py on a spare port for 6 seconds and read the exit code. Then restart pm2, confirm online, curl 200 on offramprei.com and offramp-staging. Same as the 10/3 outage rule.
  5. Service worker bump. Every app push bumps the shell version so installed phones pick up the new file on next open.
  6. Watch 30 minutes. Tail the pm2 log for 5xx and tracebacks. Open the app on two phones. Run one paid lookup and one skip trace on Ted's founding account.
  7. Rollback. git revert the release commit, bump the service worker, restart pm2, boot check, curl 200. Under 5 minutes. No data rollback needed because the app push carries no schema change.
  8. Tell people. Telegram Ted first. Founders email to the waitlist and the 4 Pro accounts with the install steps for iPhone and Android and the desktop link. Scout partners get one line in their channels.
  9. Day-after report. Signups, upgrades, lookups, skip traces, errors, and the UAT table with every cell filled.
